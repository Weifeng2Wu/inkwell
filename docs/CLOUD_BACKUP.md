# R2 / S3 项目备份

在 **设置 → 同步与备份 → R2 / S3 备份** 中配置自己的存储桶。GitHub 同步仍可同时使用。

## 配置

1. 在 Cloudflare R2、Amazon S3 或兼容 S3 的服务中创建私有存储桶，并创建 S3 API 凭据。
2. 填写端点和存储桶名称。端点中不要附加存储桶或目录。
   - R2：`https://<account-id>.r2.cloudflarestorage.com`，区域自动设为 `auto`。有地域限制的桶请使用控制台给出的端点。
   - AWS S3：`https://s3.<region>.amazonaws.com`，填写桶所在区域。
   - 兼容服务：填写服务提供的 S3 端点与区域；使用 path-style 请求。
3. 填写备份前缀，默认 `inkwell`。不同工作区可以使用不同前缀；一个前缀也可存放多个项目，历史列表会显示项目名称。
4. 填写 Access Key ID、Secret Access Key；临时凭据另填 Session Token。保存后不会回填密钥，三个输入框留空可保留已有凭据。
5. 点击 **保存配置**、**测试连接**，再用 **立即备份项目** 创建第一份快照。

端点必须使用 HTTPS；本机 MinIO 等服务可使用 localhost、127.0.0.1 或 ::1 的 HTTP 端点。不会跟随 HTTP 重定向；请使用最终端点。

凭据需要存储桶的列举权限，以及备份前缀内对象的读取和写入权限。AWS IAM 通常对应 `s3:ListBucket`、`s3:GetObject`、`s3:PutObject`；连接测试还需要 `checks/` 下的 `s3:DeleteObject`。按所用服务的权限模型，将授权限制到选定存储桶和前缀。R2 使用桶的 S3 访问密钥，而不是把控制台管理 API Token 当作 Secret Access Key。

## 自动备份间隔

建议默认 **30 分钟**；频繁改稿时可选 **15 分钟**。可选 5、15、30、60、120 分钟，初始不启用自动备份。修改开关和间隔后点击保存配置。

自动备份只在应用运行且有项目打开时执行；关闭设置页面不会停止计时。Agent、编译或 Git 同步忙碌时会推迟执行。开始前保存打开的编辑器，保存失败则停止备份。退出应用时不会额外执行云备份，现有 Git 退出同步行为保留。

每次检查会读取项目文件并计算内容哈希。没有变化时不创建重复快照，已有内容不重复上传。新的快照清单只在所需文件全部上传成功后发布；旧快照不会自动删除。该功能保留历史版本，不会自动把远端变化合并回本机。

## 备份范围与限制

- 包含当前项目中的普通文件，例如 PDF、Markdown、BibTeX、LaTeX、导图、画板、海报及图片资源。
- 不包含应用设置、账户凭据和聊天数据库。
- 跳过隐藏文件和目录（包括 `.git`、`.env`），符号链接及常见缓存目录：`node_modules`、`target`、`dist`、`build`、`out`、`__pycache__`；也跳过名为 `inkwell.sqlite` 的数据库及其 WAL/SHM。
- 不按 `.gitignore` 筛选其他文件；非隐藏的普通文件会进入备份。空目录不记录。
- 硬链接、跨平台不安全的文件名和大小写冲突会报错，避免恢复时覆盖或逸出目录。
- 单文件最多 2 GiB、项目合计最多 20 GiB、最多 50,000 个文件，快照清单最多 16 MiB。
- 配置保存在本机应用数据库；密钥使用现有独立凭据表，不写入项目文件或前端偏好设置。这里不是系统钥匙串，也没有新增本地数据库加密。

快照对象位于 `<prefix>/snapshots/`，文件内容位于 `<prefix>/blobs/`，不同快照可引用同一份内容。不要单独删除仍被快照引用的 blob，也不要为 blob 设置会提前删除内容的生命周期规则。应用不自动清理历史快照。

## 恢复

1. 保存与原备份相同的端点、存储桶、前缀和有效凭据。
2. 点击 **加载历史**，选择对应项目和时间的快照，再点击 **恢复…**。
3. 在系统目录选择器中选定存放位置。应用会创建新的 `inkwell-restored-<id>` 目录，逐个校验文件大小与 SHA-256。
4. 成功后设置页显示完整路径，可通过“打开文件夹”打开这个项目。

恢复不会覆盖现有项目。校验失败时会清理本次创建的临时目录；已有文件保留。历史界面显示此前缀下最近 100 个快照，较早快照仍在桶中。取消目录选择会取消恢复。
